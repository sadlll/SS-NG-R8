# 节点 Ping 延迟与代理可用性

用户已确认将菜单中的节点延迟改为 ping RTT，并要求修改后发版。保留真实 HTTPS 请求验证代理可用性，两项结果独立。

## 显示与策略

- 主数值使用系统 ICMP ping 三次采样的平均 RTT，单位毫秒；IPv4、IPv6 都支持。
- ping 无有效回复时显示“PING 不可用”，不使用 HTTPS 耗时或 TCP 握手冒充 ping。
- 同一行另列路径和代理状态，例如 `92.4 ms · RELAY · 可用`。ping 成功仍可能代理失败。
- 悬停分别列出 ping 目标、ping RTT、完整 HTTPS 请求耗时、测试时间及失败原因。
- 延迟排序使用 ping RTT；最快节点只在代理可用且 ping 有效的节点中选择。无 ping 不影响“代理可用”。

## 方案

沿用用户确认的独立指标方案。单独以 HTTPS 耗时代表节点延迟已被否定；仅恢复 ICMP 会丢失此前要求的真实代理验证。无 ICMP 时不做 TCP 值替代，以保持主数值含义一致。

## 实现边界

新增 PingProbe，沿用可取消且限时的进程执行器；不修改网络设置、代理凭据或正式 ss-local。每个节点先测 ping，再独立执行现有 HTTPS 验证，三节点并行。保留现有 HTTPS 超时、TLS 验证和签名更新流程。
